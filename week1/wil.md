1주차 학습내용
웹에 대해서 구체적으로 배웠다. 컴퓨터는 클라이언트-서버 모델 구조를 가지고 있다. 클라이언트가 요청을 보내면 서버에서 그 요청을 처리해 응답을 반환해 다시 클라이언트가 응답결과를 받아 사용하는 구조이다. HTTP 라는 문법을 이용해 요청과 응답을 작동시킨다. HTTP의 주요 메서드에는 GET(조회), POST(추가/등록), PUT(전체교체/새로생성), PATCH(일부수정), DELETE(삭제)가 있다.HTTP의 주요상태 코드에 대해서도 배웠다. 또한 프론트엔드와 백엔드의 차이에 대해서 구체적으로 배웠다. 백엔드는 사용자의 요청을 받아 실제 동작을 처리하고 데이터를 저장, 관리하며 그 데이터는 데이터베이스 저장소에 저장된다. 사용자가 클라이언트에 요청을 하면 서버에서 그 요청을 데이터베이스에서 가져와 다시 클라이언트에게 응답을 반환하는 구조이다. 서버에서 클라이언트로 넘어가는 과정에서 주요상태 코드가 나오는 것이다. 마지막으로 API 에 대해 배웠다. 클라이언트와 서버가 소통할 때 어떻게 요청을 보내고, 어떻게 응답할 지 등을 미리 정해놓은 규칙과 기능의 목록이다.HTTP라는 문법을 이용하나 대본이라고 생각하면 된다. REST는 가장 많이 쓰는 아키텍쳐로 구성요소로는 자원-URI(모든 자원은 고유한 ID를 가짐), 행위-Method, 표현(서버와 클라이언트가 데이터를 주고 받는 형식)이 있다. REST API는 자원을 고유한 URI로 식별하고, 해단 자원에 대한 행위를 HTTP Method로 정의하며, 그 결과를 JSON 같은 표준 형식으로 표현하는 웹 서비스 아키텍쳐 스타일이다.

작성한 온라인 쇼핑몰 프로젝트 API 명세서

- 상품 기능 
1. 상품을 등록할 수 있다. POST /stocks
2. 상품 리스트를 조회할 수 있다. GET /stocks
3. 상품 정보를 상세 조회할 수 있다. GET /stocks/{stocksid}
4. 상품 정보를 수정할 수 있다. PATCH /stocks/{stocksid}
5. 상품을 삭제할 수 있다. DELETE /stocks/{stocksid}

- 주문 기능
1. 주문 정보를 조회할 수 있다. GET /orders/{odersid}
2. 주문 내역을 수정할 수 있다. PATCH /orders/{odersid}
3. 주문을 취소할 수 있다. DELETE /oders/{odersid}
4. 주문내역 전체를 조회할 수 있다 GET /oders
5. 주문을 추가할 수 있다. POST /oders
